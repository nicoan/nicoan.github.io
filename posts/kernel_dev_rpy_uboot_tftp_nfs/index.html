Setting up a Linux Kernel dev environment with Raspberry Pi, U-Boot, TFTP and NFS

August 19, 2026 · 6 min · Nicolás Antinori

I am writing this guide basically to use it from time to time if I need it. For this to work you need:

  • Raspberry Pi (in this guide we use 3b+, but I believe anyone should do the trick).
  • Micro SD card.
  • SD card reader in the host machine.
  • USB keyboard (can be a wireless one with a dongle, but it should not be Bluetooth).

The host machine of this guide runs Debian 13. It is assumed that you know how to compile a custom kernel. I won’t enter in much detail about the commands used here, because, as I said earlier, I am basically writing this guide for my future self.

Install Raspberry Pi Os#

The first thing you need to do is to install Raspberry OS in the SD card. For this I recommend using the Raspberry Pi Imager, since it is the easiest way to install the OS and you can choose whatever option suits you better (in my case I use the minimal install).

Copying rootfs to host#

Once you have the system installed in your SD card, you’ll need to copy the rootfs partition to a folder in your host system. This folder will be the rootfs partition when booting through NFS.

First check the card’s partitions:

$ lsblk
sdc           8:32   1  14.8G  0 disk
├─sdc1        8:33   1   512M  0 part
└─sdc2        8:34   1  14.3G  0 part

In my case, the rootfs is sdc2, I proceed to mount it:

$ mkdir /tmp/rpi_rootfs
$ sudo mount /dev/sdc2 /tmp/rpi_rootfs

And then, synchronize it to a folder in the host system

$ sudo rsync -axHAWX --numeric-ids /tmp/rpi_rootfs <HOST_ROOTFS>

where <HOST_ROOTFS> is the directory where you will place the rootfs in your host machine.

Compile and install U-Boot#

U-Boot will allow us to boot a kernel image served via TFTP and mount a root file system served via NFS. First, you need to clone the repository:

$ git clone https://github.com/u-boot/u-boot.git

Before compiling it, you need to create a configuration specifically for the board you are going to use for development. In my case it is a Raspberry Pi 3b+, so I needed to execute the following command to generate the configuration:

$ cd u-boot
$ make rpi_3_b_plus_defconfig

Note: Check the configs folder to see the available board configs.

Once the configuration is in place, compile the binary:

$ make ARCH=arm CROSS_COMPILE="aarch64-linux-gnu-" -j$(nproc)

This will leave the U-Boot binaries in the repository’s root directory. The needed file is called u-boot.bin. You’ll have to copy it to the boot partition of the SD card:

$ mkdir /tmp/rpi_bootfs
$ sudo mount /dev/sdc1 /tmp/rpi_bootfs
$ cp u-boot.bin /tmp/rpi_bootfs

Later, modify the config.txt, also located in the boot partition. Add the following at the end of the named file:

[all]
enable_uart=1
kernel=u-boot.bin

With this modification, instead of booting the system, the Raspberry will boot into U-Boot.

After this step, the SD card is not needed anymore. Unmount the partitions with:

$ sudo umount /dev/sdc1
$ sudo umount /dev/sdc2

And put it in the Raspberry Pi.

Configuring TFTP#

TFTP is used to load kernel images over Ethernet. This is very useful when working with the latest kernels, since it allows you to compile new versions and boot them really quickly. First, you need to install dnsmasq package:

$ sudo apt-get install dnsmasq

Then, create the directory where the kernel image will be served:

$ sudo mkdir -p /var/tftpd

Configure dnsmasq by adding the following to /etc/dnsmasq.conf:

listen-address=<HOST_MACHINE_IP_ADDRESS>
dhcp-range=192.168.1.50,192.168.1.200,24h
enable-tftp
tftp-root=/var/tftpd

Note: 192.168.1.0/24 is the subnet where my host machine lives.

And restart the service:

$ sudo service dnsmasq restart

Configuring NFS#

Now it is time to serve the rootfs folder. First, as with the other tools, you need to install it:

$ sudo apt install nfs-kernel-server

Then add the following to the /etc/exports config file:

<HOST_ROOTFS> 192.168.1.0/24(rw,no_root_squash,async,no_subtree_check)

Export the new NFS file system and restart the service:

sudo exportfs -rav
sudo systemctl restart nfs-kernel-server

Booting the system#

I assume you have a new kernel image you want to boot, so we need to prepare the kernel image and its modules before doing anything.

All the steps in the following subsections are executed from the kernel source root directory.

Before booting#

Before doing anything, you must disable mounting the rootfs from the SD card. This must be done once, but it is an important step. Open the file located at <HOST_ROOTFS>/etc/fstab and comment the following line:

...
# PARTUUID=f619f15c-02  /               ext4    defaults,noatime  0       1
...

Note: The UUID will be different in your case.

Build a new kernel#

  1. Build the kernel image, modules and device tree bindings:

    $ make ARCH=arm64 CROSS_COMPILE="aarch64-linux-gnu-" -j$(nproc) Image modules dtbs

  2. Place the new kernel image in the TFTP directory:

    $ sudo cp arch/arm64/boot/Image /var/tftpd

  3. Install the new kernel modules in the host root fs folder:

    $ sudo make ARCH=arm64 CROSS_COMPILE="aarch64-linux-gnu-" INSTALL_MOD_PATH=<HOST_ROOTFS> modules_install

Note: Device tree bindings were compiled but not copied anywhere because they must be placed in the boot partition. If you need to modify the device tree bindings, you can copy the compiled dtbo file to the home folder and move it from there using ssh.

Booting up the Raspberry Pi#

It is time! Now that we have everything in place in the host machine, plug your Raspberry Pi to a USB keyboard, a display screen and start it. If everything goes right, you will boot into the U-Boot prompt console after some failed boot trials. This is ok, now it is time to configure U-Boot to use the kernel image in the TFTP directory and mount as the root file system the one that we are serving through NFS.

Testing the setup#

Before making the U-Boot configuration “permanent” (you can change it later :P), I believe it is a good idea to test it. Execute the following commands inside the U-Boot prompt:

U-Boot> dhcp
U-Boot> setenv serverip <HOST_MACHINE_IP_ADDRESS>
U-Boot> tftp ${kernel_addr_r} Image
U-Boot> fdt addr ${fdt_addr}
U-Boot> fdt set /chosen bootargs "console=serial0,115200 console=tty1 root=/dev/nfs nfsroot=<HOST_MACHINE_IP_ADDRESS>:<HOST_ROOTFS>,nfsvers=4.1, rw ip=dhcp"
U-Boot> booti ${kernel_addr_r} - ${fdt_addr}

If everything is configured correctly, you should boot into a new Raspberry Pi Os installation. Log-in with the user and password you specified in the Raspberry Pi Imager.

To check if you are really using the NFS root file system, in your host machine, create a file in your Raspberry’s user home directory:

$ touch <HOST_ROOTFS>/home/<YOUR_USERNAME>/TEST_NFS

and check if you can see it in the Raspberry Pi TTY using ls.

Automatically booting using TFTP and NFS#

To avoid entering the commands every time you boot, you can save the environment. To make this configuration “permanent”, enter the following commands into the U-Boot console:

U-Boot> setenv autoload no
U-Boot> setenv netboot 'dhcp; setenv serverip <HOST_MACHINE_IP_ADDRESS>; tftp ${kernel_addr_r} Image; fdt addr ${fdt_addr}; fdt set /chosen bootargs "console=serial0,115200 console=tty1 root=/dev/nfs nfsroot=<HOST_MACHINE_IP_ADDRESS>:<HOST_ROOTFS>,nfsvers=4.1, rw ip=dhcp"; bootconfig; booti ${kernel_addr_r} - ${fdt_addr}'
U-Boot> setenv bootcmd "run netboot"
U-Boot> saveenv

Conclusion#

You can develop using the SD card alone, but this setup is way more convenient because it makes working with different kernel versions, different devices and kernel modules easier. I hope you find this guide useful.
